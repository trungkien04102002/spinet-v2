Comment

Our reply

Where

C1. All metrics remain low, which suggests the model's predictive power can be equivalent to a mere guessing.

We do not think the model is guessing. On the Severe class it reaches AUC 0.899 and AUPRC 0.333, while Severe prevalence is only about 5%. A random classifier gives AUC 0.5 and AUPRC around 0.05, so the AUPRC is roughly 6.7 times chance. Macro-F1 looks low because we keep the task in its original form: three classes, the native 5% Severe rate, and macro averaging rather than accuracy. We did not resample the test set or merge classes to make the numbers look better.

Sec. 4.2, paragraph after Table 3; Severe AUC and AUPRC rows of Table 3.

C2. Notation in Section 3.1 is not defined clearly. Rewrite equations with number labelling and define the notation.

Rewritten. The three expressions that used to be inline are now numbered display equations (1) to (3), and every symbol is defined where it first appears: the encoder, the embedding dimension, the head, the label set, the prompts, the text anchors and the logit scale.

Sec. 3.1, Eq. (1) to (3).

C3. Why use a capital letter in S for the word severe?

Severe is the class name used by RSNA 2024, where the three grades are Normal/Mild, Moderate and Severe. We capitalise it when we mean the dataset label and not the ordinary adjective, and we checked that this is consistent throughout the paper. We kept it as it is.

No change made, explanation only.

C4. What is the c and d in the feature map of the CBAM block?

We have made the notation explicit. The CBAM input is now written as a rank-4 tensor with C channels over a grid of depth D, height H and width W. The c in Eq. (1) is the head function, while d is the embedding dimension (512, see Table 2); neither denotes the CBAM channel count C.

Sec. 3.1, after Eq. (1); Sec. 3.2, before Eqs. (4) and (5).

C5. The Hybrid's F1 (0.527) only exceeds others by 0.045, not 4.5 points.

Correct, and we have fixed it. F1 is on a 0 to 1 scale, so the gap is 0.045 to 0.050 in absolute macro-F1. The phrase "4.5 points" is gone.

Reviewer 2

Comment

Our reply

Where

C1. A deeper discussion of computational cost.

Training is parameter-efficient: only about 1.18 M of 260 M parameters are updated, since both backbones stay frozen, although both still run at inference. Inference is not cheap, because both backbones still have to run. The Hybrid takes 66.4 ms per IVD, about the same as the single-branch variants, and peak GPU memory is around 16 GB. The Discussion now states both sides.

Discussion, new sentence on inference cost; Table 2; Table 5; hardware row of the configuration table.

C2. Prompt engineering sensitivity.

We used a single prompt template, fixed before evaluating on SPIDER and not tuned using SPIDER examples or results. So the reported numbers are not prompt-optimised. On the other hand we have not tested paraphrases, prompt ensembles or learned prompts, so we cannot say how stable the results are. We now state this as a limitation rather than leaving it out.

Discussion, limitations paragraph; Sec. 4.3.

C3. Broader comparisons with recent vision-language medical foundation models.

We picked BiomedCLIP because it is publicly available and gives a shared image-text space that fits our slice-based input. Section 2 positions it against RadCLIP and the lumbar-specific CLIP work. A fair comparison with newer medical vision-language backbones would mean rerunning every configuration with each alternative backbone, which we could not do in the time available, so we name it as future work instead of adding a partial comparison.

Sec. 2; Discussion, future work.

Reviewer 3

Comment

Our reply

Where

C1. The zero-shot claim depends on the fused representation staying aligned with the BiomedCLIP text space, but the fusion MLP is trained through task-specific supervised heads and no loss explicitly constrains its output to match text embeddings.

We have made the procedure explicit. For the Multimodal-only and Hybrid configurations there is no linear head: the supervised RSNA loss is already a focal loss on cosine logits against the frozen BiomedCLIP text anchors, Eq. (3). Training therefore does pull the fused embedding toward the text embeddings of the source labels. What we do not have is an additional image-text contrastive objective, so nothing forces alignment with arbitrary unseen prompts. Compatibility holds for the source anchors and is only partial for distant prompts, which is what Table 4 shows. We rewrote Sections 3.1 to 3.3 so the training procedure is stated explicitly, and added a limitation naming a dedicated alignment loss as future work.

Sec. 3.1, Eq. (2) for the baselines against Eq. (3) for Multimodal and Hybrid; Sec. 3.2, task heads; Sec. 3.3; Discussion; Table 4.

C2. Explain why cosine similarity between the fused representation and unseen prompts should be semantically meaningful.

For source prompts the answer is direct: cosine is exactly what the training objective optimises, so the geometry is not accidental. For unseen prompts the property carries over only as far as the new label is semantically close to a source anchor, and we do not claim a general guarantee. Table 4 shows both sides. On disc-morphology labels that are close to the RSNA schema, cosine scoring reaches mean F1 0.587 against 0.433 for off-the-shelf BiomedCLIP, but across all eight labels the Hybrid falls below the off-the-shelf model, 0.362 against 0.394. We report the weaker case as well.

Sec. 3.1 and 3.2; Sec. 4.3 and Table 4; Discussion.
